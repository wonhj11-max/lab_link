# LabLink 논문 조사·저장·공개 가이드라인

작성: 2026-09-25. 상태: 계획 인계 지침. 이 문서 작성으로 코드·운영 DB·배포를 변경하거나 논문 조사를 실행하지 않는다.

## 1. 제품 목표와 우선순위

운영 측 에이전트가 논문을 조사하고 근거를 검증하여 Supabase에 저장한다. 일반 사용자는 연구실 상세 페이지에서 검증된 논문 정보를 열람한다. 사용자 검토·투표는 공개의 선행 조건이 아니다.

이 문서는 새 제품 방향의 기준이다. 기존 PAPER_REVIEW_RUNBOOK.md의 사용자 실행 절차와 충돌하면 이 문서가 우선한다. 기존 데이터·검토 이력은 보존한다. 이번 지침은 실행 권한이 아니며, 후속 계획/구현 요청의 범위에 따라 진행한다.

역할: Astra는 구현 가능한 설계와 작업 순서·수용 기준을 확정한다. Sol은 확정된 설계를 따라 구현하고, 조사 실행 요청을 받으면 논문별 검증·저장·체크포인트를 수행한다. 이 역할 분담은 사용자의 선택이며 모델 성능이나 비용에 대한 보장이 아니다. 자동 모델 변경·새 작업 생성은 하지 않는다.

기본 조사 범위는 기존 5개 연구실(hanyang-escml, snu-mest, snu-aeml, unist-cho, hanyang-aetl), 2022–2026년이다. 2026년은 실제 조사일까지만 포함한다. 기존 pending 큐와 공식 출판 목록을 대조하여 누락 후보도 내부 큐에 추가하는 절차를 설계한다. 기존 383건 또는 이후 381건은 과거 관측값이며 시작 시 다시 조회한다.

## 2. 사용자 화면 계약

연구실 상세 페이지의 논문 탭에 다음을 표시한다.

| 항목 | 표시 기준 |
| --- | --- |
| 제목 | 출판사 원문 제목. 긴 제목은 줄바꿈 |
| 저널·연도 | 정규화 저널명과 정식 서지 출판 연도 |
| 대표 저자 | 화면 명칭은 제1저자. 원문 첫 저자 및 명시적으로 확인된 공동 제1저자 |
| 교신 저자 | 논문 전체의 확인된 교신저자 이름. 여러 명이면 모두 표시 |
| IF | 논문 출판 연도에 해당하는 저널 JIF. 반드시 지표 연도 표시 |
| DOI | 정규화 DOI를 https://doi.org/ 링크로 연결 |
| 키워드 | 핵심 키워드 3–6개. 출판사 키워드와 AI 추출 여부 구별 |
| 논문 요약 | 버튼을 누르면 해당 카드 바로 아래에 한국어 요약이 펼쳐짐 |

대표 저자를 연구실 교수나 마지막 저자로 자동 지정하지 않는다. 공동 제1저자 표기가 없으면 공동 여부는 미확인이다. 교신저자 미확인과 교신저자가 아닌 것으로 확인된 경우를 구별한다. 현재 lab_papers.corresponding_status는 연구실 교수 개인의 상태이므로 논문 전체 교신저자 목록과 혼용하지 않는다.

요약은 미리 생성·검증해 저장하고 버튼은 저장된 요약을 펼치거나 읽어온다. 클릭 때마다 AI를 호출하지 않는다. aria-expanded/aria-controls, 키보드 조작, 모바일 줄바꿈, DOI 링크 접근성을 갖춘다. 최신 연도순·동일 연도 안정 정렬 및 페이지네이션을 적용한다. 전체 저자는 별도 펼치기로 제공할 수 있다.

값이 없으면 교신저자 미확인, 해당 연도 IF 미확인/미발표, 요약 준비 중 등 실제 상태를 표시한다. 누락값을 0이나 임의 이름으로 채우지 않는다. 요약이 없으면 버튼을 비활성화하고 이유를 짧게 표시한다.

공개 내비게이션의 논문 검토 요청과 투표 버튼을 제거한다. 기존 /paper-review 경로는 적절한 열람 페이지로 안내하거나 운영자 전용으로 전환한다. UI 숨김뿐 아니라 큐 조회·투표 RPC의 anon/authenticated 권한과 관리자 권한을 재설계한다. 일반 로그인 사용자를 운영자로 취급하지 않는다. 기존 투표·감사 기록은 삭제하지 않는다.

## 3. 조사와 근거 판정

1. DB의 공식 홈페이지와 대학 교수 디렉터리로 연구실·교수 신원을 확인한다.
2. 연구실 Publications/논문 페이지를 먼저 실제로 읽고 연도별 목록·페이지네이션을 확인한다. 연구실·연도별 인덱스를 한 번 저장한다.
3. 각 DOI의 출판사 레코드/공개 원문을 열어 제목, 저자 순서, 교신·공동 기여 표기, DOI, 저널, 날짜, 논문 당시 소속을 확인한다. Crossref는 서지 보조이고 OpenAlex는 발견용이다.
4. 공식 연구실 목록 + 독립 출판사 레코드가 일치하면 기본 검증을 통과한다. 홈페이지가 불완전하거나 접근 불가인 경우 그 사실을 기록하고 대학 공식 저장소의 해당 논문 레코드 + 출판사 원문의 교수·당시 소속 확인을 대체 경로로 허용한다. ORCID 프로필·검색 스니펫·현재 소속만으로 대체하지 않는다. 대체 경로에는 사용 이유와 두 출처를 기록한다.
5. 독립성은 URL 수가 아니라 근거의 기원으로 판단한다. 같은 원문을 복제한 저장소 두 곳만으로 두 독립 검증이라고 기록하지 않는다. 공식 소속 연결과 출판 서지 확인 각각의 근거를 남긴다.
6. DOI가 같으면 논문 한 건을 유지하고 연구실 연결은 별도로 검증한다. 동명이인, 소속 불일치, 제목 충돌, preprint/정식본 관계를 구분한다. 이전 소속 논문은 현 연구실 실적으로 자동 공개하지 않는다.
7. 정식 article/review를 기본 대상으로 한다. correction/editorial/proceedings/preprint는 구분하여 내부 보류한다. 철회·정정 상태는 별도 보존하고 공개 중 논문이 철회된 경우 표시/비공개 정책을 설계한다.
8. 온라인 공개일과 권호 날짜를 모두 저장한다. 표시 연도는 출판사 정식 서지 연도, 권호 미배정 early access는 온라인 연도 및 early access 상태를 사용한다. 연도가 변경되면 IF 연결도 재평가한다. 미래 출판을 완료된 출판으로 취급하지 않는다.

서지·연구실 연결이 검증되면 IF/교신저자/요약의 일부 누락만으로 전체 논문을 막지 않는다. 각 필드에 독립 상태를 두어 점진적으로 보강한다. 본질적인 논문 신원·연구실 연결 충돌은 내부 보류, 입증된 잘못된 후보만 제외한다. 보류 사유를 사용자에게 해결하도록 요구하지 않는다.

이전 실행에서 저장한 2건과 보류 기록도 새 기준으로 감사한다. 기존 evidence의 approve 문구만으로 재검증을 완료했다고 간주하지 않는다. 특히 공식 목록 대체 근거, 검색 스니펫만 사용했는지, 날짜·교신저자 단정 여부를 확인한다. 충돌을 발견하면 이력을 남기고 수정하며 무작정 재승인하지 않는다.

## 4. 연도별 IF 정책

당해 연도는 논문 출판 연도(Y)의 Journal Impact Factor를 뜻한다. JCR 발표 연도와 지표 연도를 분리 저장한다. Y년 지표가 아직 발표되지 않았으면 IF(Y): 미발표로 표시한다. 다른 연도 값을 당해 연도 값으로 대입하지 않는다. 필요하면 최신 확인값을 별도 줄에 실제 연도와 함께 표시하되 기본 구현에는 필수가 아니다.

Clarivate JCR의 적법하게 접근 가능한 값 또는 해당 지표 연도를 명시한 출판사 공식 저널 페이지를 근거로 한다. ISSN/eISSN 및 저널 개명 이력을 대조한다. 현재 저널 홈페이지 숫자를 과거 연도의 값으로 추정하지 않는다. CiteScore·SJR·JCI를 IF로 저장하지 않는다.

값, metric_year, release_year(확인된 경우), source_url, checked_at, 상태(verified/not_released/not_available/unverified)를 함께 저장한다. 재배포 조건을 확인하고 허용되는 값만 공개한다. 접근권 또는 공개 근거가 없으면 해당 필드만 보류한다. 저널·연도 단위로 캐시하여 논문마다 반복 조사하지 않는다.

IF는 저널 지표이며 개별 논문의 품질 점수가 아니라는 짧은 설명을 툴팁/도움말에 둔다. 공식 참고: https://clarivate.com/academia-government/scientific-and-academic-research/research-funding-analytics/journal-citation-reports/

## 5. 요약과 키워드

합법적으로 접근 가능한 초록 또는 본문을 읽고 한국어로 3–5문장(권장 300–600자)을 작성한다. 연구 목적, 접근법, 주요 결과, 의의·한계를 담되 근거에 없는 항목은 생략한다. 제목만으로 생성하지 않는다. 초록 기반이면 초록 기반 요약이라고 표시하고, 본문 전체 검토로 표현하지 않는다.

수치·단위·비교 조건·실험 규모·인과 표현을 원문과 대조한다. 초록에 없는 한계·상용화 가능성·최고 성능 등을 창작하지 않는다. 별도 검증 단계에서 주장별 출처 위치를 확인하고 통과된 버전만 공개한다. 긴 원문 복사나 단순 번역문을 공개 요약으로 저장하지 않는다.

키워드는 출판사 author keywords를 우선 보존하고, 없거나 탐색에 부족하면 읽은 초록/본문에서 3–6개를 추출한다. 재료/현상/방법/응용을 적절히 포함하되 근거 없는 분류는 추가하지 않는다. AI 추출임을 표시하고 한·영 용어, 약어·동의어를 관리한다. 사용자 태그와 원저자 키워드를 구분한다.

요약·키워드마다 source_url, source_basis, retrieved_at, source_hash, 생성 모델 식별자(확인 가능한 실제 값), prompt_version, generated_at, verification_status, verified_at를 보존한다. 검증자 역할은 에이전트로 명시하며 사람이 검토한 것처럼 기록하지 않는다. 원문 자료 저장은 이용 조건에 맞게 최소화하고 내부 근거와 공개 콘텐츠를 분리한다.

## 6. Astra가 확정할 데이터 설계

현재 src/main.tsx의 LabDetail은 papers(*)를 읽고 summary를 직접 표시한다. public.papers에는 기본 서지와 요약만 있고 lab_papers에는 교수 1명과 교신 상태만 있다. 전체 저자, 키워드, 연도별 IF는 신규 설계가 필요하다. 아래는 권장 방향이며 실제 SQL/API 계약은 Astra가 확정한다.

| 단위 | 필수 내용 |
| --- | --- |
| papers | DOI 유일성, 제목, journal_id, 서지/온라인 날짜, 연도, 문헌 유형, 출판·철회 상태 |
| paper_authors | paper_id, 순서, 원문 이름, ORCID(선택), 논문 당시 소속, 제1/공동 제1/교신 역할별 확인 상태와 근거 |
| journals / journal_identifiers | 저널명, ISSN/eISSN, 개명·식별 연결 |
| journal_metrics | journal_id + metric_type + metric_year 유일키, 값 또는 명시 상태, 지표 출처 |
| paper_summaries | 한국어 요약, 근거 범위, 생성·검증 버전, 공개 버전 |
| paper_keywords | 원문/추출 구분, 정규화 용어·언어·근거·버전 |
| lab_papers | 기존 연구실 연결 유지, 교수와 저자 레코드 연결, 당시 소속 검증 |
| private evidence / runs | 근거별 주장, 판정, 충돌, run_id, 진행·재시도·감사 이력 |

관계형/JSONB 선택, nullable/unknown 의미, 유일키, 인덱스, 제약, 공개 응답 DTO를 구체적으로 명세한다. 공개 뷰는 원본 private 큐·내부 프롬프트·개인 토큰을 노출하지 않으며 Supabase RLS를 우회하지 않도록 권한과 뷰 실행 방식을 검증한다.

기존 승인 RPC는 전체 저자/키워드/IF를 저장하지 않는다. 확장 RPC 또는 서버 전용 원자적 저장 절차가 필요하다. 논문·저자·연결의 부분 저장을 방지하고 DOI+연구실 연결 및 run/action key로 멱등성을 보장한다. 타임아웃 후 상태를 조회한 뒤 재시도한다. 공유 논문 수정은 연결된 모든 연구실에 영향을 주므로 기존 값 충돌 시 보류한다.

마이그레이션은 추가형으로 시작하여 기존 summary/summary_basis/summary_reviewed_at와 호환한다. 백필 후 새 읽기 경로로 전환한다. 기존 열·RPC 제거는 의존성 확인 후 별도 단계로 둔다. 서비스 키는 서버/비밀 환경변수에서만 사용한다.

## 7. Astra 계획 산출물과 Sol 실행 순서

Astra는 pipeline/PAPER_PUBLICATION_PLAN.md에 다음을 확정한다: 범위, 위 정의의 해석, ERD 또는 테이블 계약, 마이그레이션·백필·복구 순서, 권한/RLS, 서버 저장 API와 공개 DTO, 컴포넌트 분리, 조사·요약 검증 규칙, IF 누락 정책, 단계별 변경 파일·수용 기준·테스트. 필요하면 구현과 데이터 조사 작업표를 분리한다. 논문 일괄 수집·운영 DB 변경은 계획 단계에 포함하지 않는다.

Sol의 권장 실행 단계:

1. 계획과 현재 코드/DB/체크포인트를 대조하고 미해결 설계 문제를 기록한다.
2. 추가형 스키마와 서버 저장 경로, 권한, 검증 규칙을 구현한다.
3. 공개 논문 DTO·카드·요약 펼치기·키워드와 누락 상태를 구현하고 사용자 투표 동선을 전환한다.
4. 소규모 검증 표본으로 end-to-end 저장과 공개 표시를 확인한다. 표본에는 여러 교신저자, 교신 미확인, IF 미발표, 초록만 있는 논문, 연구실 공동 연결을 포함한다. 테스트용 가짜 논문은 운영에 공개하지 않는다.
5. 조사 실행 권한 범위에서 기존 승인분을 감사하고 pending/누락 후보를 연구실·연도별 최대 10건씩 처리한다.
6. DB 저장 후 공개 읽기 응답을 대조하고 배포 요청 범위에서 운영 화면까지 확인한다.

현재 요청은 가이드라인 작성이다. 후속 실행 요청에서 허용된 구현·데이터 저장·배포 범위를 이어받고 이미 주어진 권한은 반복 확인하지 않는다.

## 8. 체크포인트와 저토큰 운영

work/paper-publication/<run_id>/에 scope.json, source-index/<lab-year>.json, batches/<batch_id>.json, evidence/<doi-key>.json, payloads/<doi-key>.json, checkpoint.json, exceptions.json을 저장한다. DOI 문자열의 슬래시를 파일 경로로 쓰지 말고 해시 등 안전한 키를 사용한다. 기존 work/paper-review/ 기록은 유지하고 참조한다.

scope에는 최초 후보 ID 목록, 공식 목록 추가 후보 ID, 기간, 기준시각, 계획 버전을 기록한다. checkpoint에는 처리된 ID별 단계(discovered/verified/enriched/persisted/readback_verified/held/rejected), 다음 ID, paper_id, source_hash, 마지막 성공시각, 오류·재시도 횟수를 남긴다. 시각은 실제 실행 시각을 사용한다.

매 논문 저장 후 갱신하며 중단 후 DB 상태와 대조해 재개한다. 최초 대상 + 추가 후보 = 저장 완료 + 보류 + 제외 + 미처리로 대조하고 필드별 요약/IF/교신 미확인 수를 별도 보고한다. DOI 고유 수와 연구실 연결 수를 분리한다.

연구실 목록은 연구실·연도별, IF는 저널·연도별, 논문 근거는 DOI·source_hash별로 캐시한다. 모델에는 현재 배치의 필요한 필드와 짧은 근거만 전달한다. 장문 HTML/전체 큐를 반복 입력하지 않는다. 검색 스니펫만으로 승인하지 않는다. 접근 오류는 제한 재시도 후 이유를 남겨 다음 항목으로 진행한다. 요약 검증 실패는 요약만 재처리한다.

work/는 현재 Git ignore 대상이므로 로컬 체크포인트만으로 장기 보존을 보장하지 않는다. Sol은 비밀정보를 제외한 실행 상태·근거를 서버 private 저장소/테이블에도 보존하는 방식을 구현한다. 가이드와 계획은 버전 관리 대상으로 유지한다.

## 9. 완료 기준

- 비로그인 사용자가 연구실 논문 제목·저널·연도·제1저자·교신저자·연도 표시 IF·DOI·키워드를 볼 수 있고 요약을 카드 아래에서 펼치고 접을 수 있다.
- 누락 필드가 명확하고 잘못된 연도 IF, 추정 교신저자, 제목만 보고 쓴 요약이 없다.
- 일반 사용자는 내부 큐/승인/투표에 접근하지 못한다. 공개 논문 조회와 로그인 등 기존 기능은 유지된다.
- DOI 중복, 공동 연구실 연결, 재실행, 타임아웃 재시도, 누락 메타데이터, RLS 권한, 요약 근거 검증을 의미 있는 테스트로 확인한다.
- npm test와 npm run build를 통과하고 개발/테스트 DB에서 마이그레이션과 공개 읽기를 검증한다. 운영 적용 후 표본 조회와 모바일·키보드 요약 조작을 확인한다.
- 데이터 작업은 전체 범위의 저장/보류/제외/미처리가 집계된다. 미처리가 남으면 전체 완료라고 보고하지 않는다. 한 필드 접근 제한은 독립적으로 처리 가능한 논문 작업을 중단시키지 않는다.

## 10. 복사해서 사용할 요청문

### Astra 계획 요청

LabLink의 pipeline/PAPER_PUBLICATION_GUIDELINES.md와 기존 코드·스키마·체크포인트를 읽고 운영자가 조사·검증하여 공개하는 논문 서비스의 구현 계획을 pipeline/PAPER_PUBLICATION_PLAN.md에 작성해줘. 제목, 저널, 제1·공동 제1저자, 전체 교신저자, 논문 출판 연도 IF, DOI, 저장된 한국어 요약 펼치기, 키워드를 포함해줘. 데이터 모델·RPC·RLS·마이그레이션·백필·컴포넌트·테스트·단계별 완료 기준을 Sol이 바로 구현할 수준으로 확정해줘. 이번에는 계획만 작성해줘.

### Sol 구현·조사 요청

LabLink의 pipeline/PAPER_PUBLICATION_GUIDELINES.md와 pipeline/PAPER_PUBLICATION_PLAN.md를 읽고 확정된 계획을 구현해줘. 기존 데이터와 이력을 보존하고 테스트 후, 5개 연구실 2022–2026년 논문을 공식 목록과 출판사 근거로 검증하여 Supabase에 저장해줘. 기존 승인분도 근거를 감사하고 누락 후보를 포함해줘. 요약·키워드는 읽은 자료로 생성·검증하고 IF는 해당 지표 연도와 출처를 남겨줘. 논문별 체크포인트를 기록하며 순차 진행하고, 접근할 수 없는 필드는 사유를 남긴 뒤 나머지를 계속해줘. 운영 사이트 배포까지 진행하고 공개 화면과 저장 결과를 확인해줘.
